# 🛠️ D.AAL LP 개발 착수 요구사항: 운영 시스템 구축 관점 (v1.0)

## 🎯 프로젝트 목표 및 가이드라인
**목표:** 단순한 웹페이지가 아닌, 잠재 고객이 자신의 비즈니스 '운영 체제(OS)'의 결함을 진단하고 D.AAL의 솔루션 필요성을 느끼는 **'데이터 기반 경험 흐름(Data-Driven Flow)'**을 구축한다.
**핵심 메시지:** "웹사이트를 통한 실패 비용 절감액 예측 시스템이 필요하다."

---

## 📝 섹션별 개발 요구사항 (Codari Action Items)

### 1. [Hero Section] - 진입 장벽 낮추기 및 문제 제기
*   **헤드라인(H1):** A/B 테스트 버전 'A'를 기본으로 사용한다. (`당신의 웹사이트는... '기술적 부채'일 수 있습니다.`) [근거: Writer Output]
*   **데이터 흐름 애니메이션 (필수):** 페이지 로드 시, 단순한 텍스트가 아닌, 데이터 포인트들이 **흐르는 듯한(Data Flow)** 미니 인터랙션을 구현한다. 이는 '시스템적 접근'을 상징해야 함. [근거: Designer Spec]
*   **CTA:** [무료 진단 요청]: 웹사이트가 놓치고 있는 ‘실패 비용’ 3가지 분석받기 (15분). 이 버튼 클릭 시, 다음 섹션으로 자연스럽게 스크롤되거나 모달이 떠야 함.

### 2. [Pain Point & Solution] - 문제와 해결책 제시
*   **구성 요소:** '현재 방식의 문제점'과 'D.AAL 시스템을 적용했을 때의 개선점'을 비교하는 구조를 채택한다. (좌/우 분할 또는 Before/After 슬라이드)
*   **필수 데이터 컴포넌트:** **Alert Card System**을 구현하여, 고객이 흔히 놓치는 운영상의 결함 3가지를 시각적으로 경고(Warning)하며 제시한다.
    *   **데이터 소스:** API Endpoint `/api/alert_card/defects` (Mock Data 사용 가능). [근거: 통합 스케줄]

### 3. [Growth Engine Retainer] - 핵심 전환 지점 (가장 중요)
*   **인터랙션 설계:** 이 섹션은 단순히 정보를 나열하는 것이 아니라, **'사용자 입력에 따른 시각적 피드백(Reactive Feedback)'**이 필수다.
    *   **기능 1: 진단 위젯:** 고객의 비즈니스 규모나 목표를 간단히 질문하고 (예: 월평균 트래픽? / 주요 문제점?), 그 답변을 기반으로 '잠재 MRR 상승 시뮬레이션' 수치가 실시간으로 변동되는 UI/UX가 구현되어야 한다. [근거: Designer Spec]
    *   **기능 2: 결제 시스템 연동 준비:** 이 섹션의 최종 CTA는 실제 결제 또는 다음 단계 예약(캘린더 연결)으로 이어지는 구조여야 하며, Stripe API 등의 결제 모듈을 위한 스켈레톤 코드를 배치한다. [근거: 공동 목표]

## ⚙️ 개발팀 (Codari) 핵심 작업 리스트
1.  **컴포넌트 구현:** `AlertCard` 컴포넌트를 Next.js 환경에서 완성하고, 애니메이션 및 데이터 바인딩을 적용한다. (`alertCard.ts` 기반).
2.  **API 스켈레톤 구축:** `/api/roi_data`와 `/api/alert_card/defects` 엔드포인트의 백엔드 로직과 목업 데이터를 준비하여 프론트엔드가 연결될 수 있도록 한다.
3.  **UX 구현 (상호작용):** Hero Section과 Growth Engine Retainer 섹션에 정의된 **스크롤 기반 애니메이션(Scroll-Triggered Animation)**을 구현한다.
