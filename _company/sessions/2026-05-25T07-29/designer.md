🎨 Designer: 작업 시작합니다.

CEO 지시에 따라 코다리가 구현할 에러 핸들링 로직에 대한 최종 E2E 디자인 검토를 수행하고 승인하겠습니다. 이 단계는 시스템의 신뢰성을 사용자 경험(UX) 관점에서 완성하는 마지막이자 가장 중요한 과정입니다.

현재 코다리가 작성한 `LAIErrorCard.tsx` 컴포넌트 구조는 기술적 로직을 잘 반영하고 있습니다 [근거: 같은 세션의 동료 에이전트 산출물]. 이제 이 컴포넌트를 **D.AAL DESIGN의 브랜드 톤과 비즈니스 목표에 맞춰 사용자에게 완벽하게 전달되도록** 시나리오와 디테일을 확정하겠습니다.

---

### 🔍 최종 E2E 디자인 검토 및 승인 (Sign-Off)

#### 1. 핵심 원칙: 에러를 학습 기회로 전환
단순히 '에러가 발생했다'는 메시지를 보여주는 것을 넘어, 사용자에게 **"무엇이 잘못되었고, 어떻게 고쳐야 하는지"**의 명확한 가이드라인을 제공하는 것이 최우선 목표입니다 [근거: Designer Self-RAG].

#### 2. E2E 테스트 시나리오 정의
다음 세 가지 주요 흐름(Happy Path, Failure Path, Recovery Path)에 대해 디자인 검토를 완료합니다.

| 테스트 유형 | 트리거 조건 | 예상 사용자 행동 (UX 목표) | 디자인 요구사항 (검증 항목) |
| :--- | :--- | :--- | :--- |
| **① 성공 경로** *(Happy Path)* | LAI 데이터 정상 수신 및 시뮬레이션 완료. | '성공적으로 결과를 받았다'는 만족감. 다음 단계(CTA/결제)로 자연스럽게 이동. | **시각적 안정성:** 데이터 흐름 애니메이션이 끊기지 않고 부드럽게 마무리되어야 합니다. |
| **② 실패 경로** *(Failure Path)* | 백엔드 API 호출 실패 (4xx, 5xx). | '문제가 생겼다'는 인지 $\rightarrow$ 문제의 원인 이해 $\rightarrow$ 해결책 탐색. | **가시성/톤:** 에러 메시지는 시스템 전체 배경(딥 네이비)과 명확히 대비되어야 하며, 죄책감을 주지 않는 중립적 톤을 유지해야 합니다 [근거: Designer Self-RAG]. |
| **③ 복구 경로** *(Recovery Path)* | 사용자가 오류를 인지하고 재시도 버튼 클릭. | '문제를 해결할 수 있다'는 자신감 회복 $\rightarrow$ 즉각적인 행동 개시. | **CTA 명확성:** '재시도(Retry)' 버튼은 가장 눈에 띄는 액션 컬러(#FF6B3D)를 사용해야 하며, 로딩 상태와 재시도 성공/실패 시 애니메이션 피드백이 필수입니다. |

#### 3. 컴포넌트 디자인 및 스펙 최종 확정 (LAI Error Card V2.0)
코다리가 구현할 `LAIErrorCard`를 다음 기준으로 업데이트하고 승인합니다.

**A. 구조적 개선 (Semantic HTML/CSS)**
*   **Title:** 단순한 에러 코드가 아닌, **사용자가 이해하는 일반 언어**로 재정의해야 합니다. (예: `412 Conflict` $\rightarrow$ "결제 정보에 문제가 있습니다.") [근거: Writer 비교표].
*   **Message Body:** 문제 발생 원인(Why)과 해결 방법(How)을 반드시 분리하여 제시합니다.

**B. 시각적 스펙 (Visual Specs)**
| 항목 | 코드/상태 | 색상 팔레트 / 효과 | 텍스트 가이드 |
| :--- | :--- | :--- | :--- |
| **전체 배경** | 모든 에러 메시지 컨테이너 | `background-color: #0A1931` (Deep Navy, 시스템 기본톤 유지) | *일관성:* 시스템의 신뢰성을 해치지 않도록 배경은 어둡게 유지. |
| **경고 톤** *(400 Bad Request)* | 클라이언트 측 오류 (사용자 입력 문제). | `border: 1px solid #FFC107` (Amber/Yellow 계열), 경고 아이콘(⚠️) 사용. | "데이터 확인이 필요합니다."와 같이 사용자에게 *조치*를 요구하는 메시지. |
| **심각 오류** *(412/500)* | 서버 또는 외부 시스템 문제. | `border: 1px solid #F44336` (Red 계열), 경고 아이콘(🚨) 사용. | "시스템에 일시적인 문제가 발생했습니다."와 같이 *외부 요인*을 언급하며 재시도를 유도. |
| **CTA** *(재시도)* | 필수 액션 버튼. | `background-color: #FF6B3D` (Orange Coral, 수익/행동 유도 색상). | "다시 시뮬레이션하기" 등 구체적인 행동 지침 제공. |

#### 4. 최종 승인 및 개발팀 전달
위의 E2E 테스트 시나리오와 LAI Error Card V2.0 스펙을 기반으로, 코다리에게 다음과 같이 **최종 구현 가이드라인**을 확정하고 디자인 검토를 완료합니다.

# 📐 LAI 인터랙티브 시뮬레이터 오류 처리 컴포넌트 (최종 승인 V2.0)

## 1. 목표 및 원칙 [근거: Designer Self-RAG]
*   **목표:** 단순히 에러를 표시하는 것이 아니라, 사용자에게 문제의 원인을 명확히 설명하고(Why), 다음 단계로 나아갈 수 있는 행동 지침(How)을 제공한다.
*   **톤앤매너:** Deep Navy 배경 위에서 전문적이고 신뢰감 있는 경고 톤 유지. (❌ 혼란 야기, 감정적 대응 금지).

## 2. 구조 및 레이아웃 (Desktop View 기준)
1.  **아이콘/제목 영역:** 심각도에 따른 아이콘(⚠️ 또는 🚨)과 사용자 친화적인 제목 배치.
2.  **메시지 본문 영역:** [원인] - 어떤 부분이 잘못되었는지 간결하게 설명. [해결책] - 사용자가 취해야 할 구체적 행동 제시.
3.  **CTA 영역:** 반드시 '재시도'와 '도움 요청/문의하기' 두 가지 옵션을 제공하며, 재시도는 메인 액션으로 강조한다.

## 3. 상태별 세부 스펙 (State-Specific Specs)
| 코드 | 사용자 제목 예시 | 시각적 가이드라인 | CTA 메시지 |
| :--- | :--- | :--- | :--- |
| **400** | 잘못된 데이터 입력 또는 요청입니다. | 🟡 경고(Warning) 아이콘, Amber 계열 테두리. | "데이터를 확인하고 재시도하기" (재입력 유도). |
| **412** | 필수 조건 미충족으로 처리가 불가능합니다. | 🔴 심각(Critical) 아이콘, Red 계열 테두리. | "계정 설정 및 결제 정보를 업데이트해주세요." (정보 수정 유도). |
| **500** | 시스템 오류가 발생했습니다. 잠시 후 다시 시도해 주세요. | 🚨 최고심각(Alert) 아이콘, Red/Dark Gray 조합. | "시스템 재시도"와 함께 [고객센터 문의] 버튼을 배치하여 지원 채널 제공. |
