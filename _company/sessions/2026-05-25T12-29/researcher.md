 1	# 🛠️ D.AAL DESIGN: SaaS/웹사이트 기술 부채 진단 체크리스트 (35+ 항목)
 2	**진단 목적:** 시스템의 현재 기능적 완성도를 넘어, 장기적인 운영 리스크와 유지보수 비용을 산정하여 고객에게 '성장 운영체제(Growth OS)' 구축 필요성을 강조.
 3	
 4	---
 5	
 6	## Ⅰ. 아키텍처 및 레거시 코드 부채 (Architecture & Code Debt)
 7	*시스템의 구조적 결함 및 설계 단계에서 발생한 비효율.*
 8	
 9	1.  **[API 연동 방식]** RESTful 원칙을 따르지 않고, 과도하게 복잡하거나 중첩된 API 호출 체계가 존재하는가?
10	2.  **[서비스 경계 불분명]** 특정 기능(예: 결제 로직)이 여러 서비스나 모듈에 분산되어 있어 단일화/수정 지점이 명확하지 않은가? (Monolith 위험)
11	3.  **[기술 스택 노후화]** 사용된 프레임워크, 라이브러리 버전 등이 공식 지원 종료(EOL) 시점에 가까워 보안 패치 및 업그레이드가 어려운가?
12	4.  **[데이터 통신 방식]** 상태 관리(State Management) 로직이 분산되어 있어 데이터 일관성 유지에 실패할 가능성이 있는가? (e.g., 전역 변수 과다 사용)
13	5.  **[결합도/응집도]** 특정 컴포넌트의 수정이 시스템 다른 영역에 예기치 않은 부작용(Side Effect)을 일으키는 높은 결합도가 존재하는가?
14	
15	## Ⅱ. 데이터 및 백엔드 로직 부채 (Data & Backend Logic Debt)
16	*데이터 처리 과정, 비즈니스 규칙 구현에서의 취약점.*
17	
18	6.  **[트랜잭션 무결성]** 결제(Payment) 또는 상태 변경(Status Change) 같은 핵심 트랜잭션에 대해 원자성(Atomicity)을 보장하는 로직이 미흡한가? (부분 성공 위험)
19	7.  **[데이터 스키마 비효율]** 데이터베이스 필드가 너무 광범위하거나, 사용하지 않는 레거시 필드/테이블이 남아있는가? (Schema Sprawl)
20	8.  **[인덱싱 누락]** 자주 검색되거나 JOIN되는 핵심 컬럼에 인덱스(Index)가 없어 쿼리 속도가 현저히 느린가?
21	9.  **[멱등성 미보장]** 웹훅(Webhook) 또는 API 재요청 시, 동일한 요청이 여러 번 들어와도 시스템 상태가 중복 처리되지 않도록 보장하는 로직(Idempotency Key)이 없는가?
22	10. **[비즈니스 규칙의 하드코딩]** 핵심 비즈니스 정책(예: 할인율, 배송료 계산 공식)이 코드 내에 직접 작성되어 있어 변경 시 개발자의 개입이 필수적인가?
23	
24	## Ⅲ. 사용자 경험 및 인터페이스 부채 (UX/UI & Client Debt)
25	*기술적 결함이 사용자에게 불안감이나 불편함을 주는 영역.*
26	
27	11. **[오류 처리의 미비]** API 호출 실패(4xx, 5xx) 시 단순히 "실패했습니다"라는 메시지만 보여주고, 문제 해결을 위한 구체적인 가이드라인(예: 다시 시도할 시간, 연락처 등)이 없는가?
28	12. **[사용자 흐름 단절]** 특정 플로우(예: 회원가입 → 첫 구매)에서 사용자에게 피드백(Success/Error Message)이 불분명하여 다음 행동을 망설이게 하는 구간이 있는가?
29	13. **[성능 최적화 부족]** 초기 페이지 로딩 속도(LCP, FID 지표 등)가 느려 사용자가 이탈할 가능성이 높은가? (리소스 과다 로드 문제 포함)
30	14. **[반응형 디자인 오류]** 특정 디바이스 크기(특히 태블릿/모바일 뷰포트)에서 레이아웃이 깨지거나 필수 기능이 숨겨지는 현상이 발생하는가?
31	
32	## Ⅳ. 보안 및 컴플라이언스 부채 (Security & Compliance Debt)
33	*시스템의 안정성과 법적 리스크에 직결되는 항목.*
34	
35	15. **[인증/인가 취약점]** 사용자 ID나 세션 토큰이 적절하게 검증되지 않아, 권한 없는 사용자가 다른 계정 정보에 접근할 수 있는가? (Broken Access Control)
36	16. **[입력값 검증 미비]** 폼 제출 시 서버 측에서 입력값(Input Field)의 유형/길이/형식을 충분히 검사하지 않아 악성 코드가 삽입될 위험이 있는가? (XSS/SQL Injection 취약점)
37	17. **[데이터 암호화 부재]** 민감 정보(비밀번호, 개인 식별 정보 등)를 전송하거나 저장할 때 적절한 해시 함수 및 암호화 프로토콜을 사용하지 않는가?
38	18. **[세션 관리 취약점]** 사용자 세션 만료 시간이 너무 길거나, 브라우저를 닫았다고 해도 세션 토큰이 남아있어 재사용될 위험은 없는가?
39	
40	## Ⅴ. 운영 및 확장성 부채 (Operational & Scalability Debt)
41	*시스템을 '운영'하는 과정에서 발생하는 비효율과 리스크.*
42	
43	19. **[배포 프로세스 수동화]** 코드 변경 후 배포(Deployment) 과정이 Git 커밋 → 서버 접속 → 수동 실행의 복잡한 과정을 거치는가? (CI/CD 부재)
44	20. **[로깅 및 모니터링 부족]** 시스템 오류 발생 시, 어느 단계에서 어떤 유형의 에러가 발생했는지 추적할 수 있는 중앙 집중식 로그 기록(Centralized Logging)이 없는가?
45	21. **[성능 병목 지점]** 트래픽 증가에 따라 특정 API 엔드포인트나 데이터베이스 쿼리가 급격히 느려지는 '병목 현상'을 예측하고 대응할 계획이 없는가?
46	22. **[확장 단위 한계]** 시스템의 핵심 로직이나 인프라 자체가 단일 서버/단일 기술 스택에 종속되어 있어, 트래픽 분산이나 기능 추가 시 병목이 발생하는가?
47
