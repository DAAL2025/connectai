기술적 QA 로드맵과 코다리 개발팀이 정의한 경계 조건(4xx, 5xx)은 단순한 실패 메시지를 넘어, **사용자에게 '무엇이 문제인지', 그리고 '어떻게 해결해야 하는지'**를 알려주는 교육 자료이자 신뢰 구축의 기회여야 합니다.

일반적인 에러창 대신, 기능별/상황별로 명확히 구분되는 3가지 핵심 실패 메시지 컴포넌트(Error State Component) 디자인 목업을 제작하겠습니다. 이 스펙은 개발팀이 즉시 구현 가능하도록 구조화된 Figma Spec 형식으로 제시합니다.

## 🎯 1. 목표 및 원칙
*   **목표:** 사용자가 오류 코드(4xx, 5xx)를 보고 당황하거나 포기하는 것을 방지하고, 다음 단계의 행동을 명확히 유도한다.
*   **원칙:** 사용자 경험 최우선 (UX First). 기술적 메시지는 최소화하고, '행동 가능한 가이드' 제공에 집중한다.

## 🎨 2. 기본 디자인 시스템 및 컨셉
*   **톤앤매너:** 경고(Warning)의 느낌을 주되, 패닉 상태가 아닌 '진단 가능'한 느낌이어야 합니다. (System Diagnostic Tone).
*   **색상 코드:**
    *   배경: `#FAFAFA` (오류를 강조하기 위해 일반 배경보다 약간 어둡게)
    *   주요 경고 텍스트: `Deep Red (#D9534F)` - 시스템의 실패나 위험을 상징.
    *   보조 안내/가이드 텍스트: `Gray (#6C757D)` - 진정하고 차분한 해결책 제시.
*   **시각 요소:** 경고 아이콘(⚠️) 또는 시스템 연결이 끊어진 듯한 와이어프레임 느낌의 배경 패턴을 활용합니다.

## 💻 3. 상황별 컴포넌트 상세 스펙 (State-Specific Components)

### [Type A] 유효성 검사 실패 메시지 (Validation Error / HTTP 400 Bad Request)
*   **발생 조건:** 사용자가 필수 입력 필드를 비워두거나, 데이터 형식이 잘못된 경우. (Client Side Input Failure).
*   **디자인 목표:** 문제가 발생한 **특정 입력 필드 바로 아래**에 표시되어야 하며, 해당 필드만 빨간색으로 포커스를 받아야 합니다.
*   **구조:**
    1.  **필드 레이블 근처:** 작은 ⚠️ 아이콘 + "이 항목은 필수입니다." (Red Text)
    2.  **메시지 바디:** "LAI 계산을 위해 '참고 자료 출처'를 반드시 입력해 주십시오. (최소 5글자)" [근거: 코다리/영숙의 QA 로드맵]
*   **개발 가이드:** 이 컴포넌트는 부모 컴포넌트(Input Field)와 결합되어 작동하며, 오류 메시지 자체는 **`Tooltip` 또는 `Inline Error Message`** 형태로 구현됩니다.

### [Type B] 비즈니스 논리 실패 메시지 (Logic Failure / HTTP 412 Precondition Failed)
*   **발생 조건:** 데이터 형식은 맞으나, 시스템이 정의한 *비즈니스 규칙*에 위배되는 경우. (예: 선택된 구독 플랜의 기준 매출액을 충족하지 못함). [근거: 현빈 보고서/Growth Logic]
*   **디자인 목표:** 사용자가 '왜 안 되는지'를 이해시키고, **다음 행동을 유도**해야 합니다.
*   **구조:** (전체 섹션 하단에 배치)
    1.  **헤드라인:** "⚠️ 조건을 충족하지 못했습니다." (Deep Red Text, H3 크기)
    2.  **본문 설명:** "현재 입력하신 데이터 흐름으로는 'Premium' 플랜의 최소 요구치(월 500만원)에 도달하지 않아 시뮬레이션이 불가능합니다." [근거: 현빈/Growth Logic]
    3.  **해결 가이드 (핵심):** **"💡 해결 방법:"** 이라는 박스 처리된 강조 섹션을 만듭니다. "필요한 조건을 충족시키려면, '추가 데이터 흐름 감사'를 먼저 받거나, 월 매출 예측치를 상향 조정해주세요."
    4.  **CTA:** "→ 시스템 감사 요청하기" (주황 코랄 버튼)

### [Type C] 시스템 오류 메시지 (System Failure / HTTP 500 Internal Server Error)
*   **발생 조건:** 서버 내부 문제, 네트워크 장애 등 개발팀이 통제할 수 없는 상황.
*   **디자인 목표:** 사용자가 혼란스럽지 않게 안심시키고, **기술 지원을 통해 해결할 경로**를 제공해야 합니다. (가장 중요한 신뢰도 유지 단계)
*   **구조:** (화면 전체에 오버레이되는 Modal 또는 섹션)
    1.  **헤드라인:** "❌ 시스템 오류가 발생했습니다." (Deep Red Text, H2 크기)
    2.  **공감/사과:** "죄송합니다. 현재 LAI 시뮬레이터 백엔드에 일시적인 문제가 발생하여 정상 작동할 수 없습니다." [근거: QA 로드맵]
    3.  **기술적 설명 (최소화):** "오류 코드 500입니다. 이 문제는 개발팀에서 즉시 확인하고 수정하는 과정이 필요합니다."
    4.  **사용자 행동 가이드:** **"🛠️ 고객님께서 해보실 수 있는 조치:"**을 제시합니다.
        *   ✅ 새로고침 버튼 (Refresh)
        *   ✅ 잠시 후 다시 시도하기 (Try Again Button)
    5.  **최종 지원:** "문제 해결이 어렵다면, 아래 연락처로 문의해주세요. 담당자가 바로 확인하겠습니다." + **[연락처 정보]**
