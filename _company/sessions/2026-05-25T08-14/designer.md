# 🎨 D.AAL DESIGN - API 오류 핸들러 최종 디자인 스펙 (Version 2.0)

## 🎯 디자인 목표 및 원칙
1.  **오류를 학습 기회로 전환:** '실패'라는 감정적 경험을 '진단(Diagnosis)' 또는 '피드백(Feedback)'이라는 데이터 기반의 과정으로 재설정합니다.
2.  **브랜드 일관성 유지:** 모든 에러 상태에서도 메인 브랜드 컬러(딥 네이비, 오렌지 코랄)와 폰트 계층 구조를 유지합니다.
3.  **가시적 해결 경로 제시:** 단순히 오류 코드만 보여주는 것이 아니라, **'무엇을 고쳐야 하는지(What to fix)'** 와 **'다음 단계는 무엇인지(Next Action)'** 를 명확히 분리하여 안내합니다.

## 🛠️ 공통 컴포넌트 스펙 (Global Components)
### A. 에러 컨테이너 구조 (`Error-Container`)
*   **레이아웃:** 중앙 정렬, 최대 너비 700px의 카드형 컴포넌트로 배치됩니다.
*   **배경:** 배경색은 `#F8F9FA` (옅은 그레이)로 하여 메인 콘텐츠와 시각적으로 구분되지만, 너무 무겁지 않은 느낌을 유지합니다.
*   **제목 (`Error Title`):** 에러 메시지의 감성적 톤을 담당합니다. 크기: 24px, Weight: Bold. 색상: `#A03B57` (주의를 주는 적절한 컬러). 예시: "데이터 진단 필요", "작업에 필요한 전제 조건이 충족되지 않았습니다."

### B. 상세 오류 메시지 (`Error Description`)
*   **레이블:** 시스템적 원인을 간결하게 설명합니다. 크기: 16px, Weight: Regular. 색상: `#495057` (중립적인 다크 그레이).
*   **본문:** 사용자에게 구체적으로 무엇이 문제인지 설명합니다. 최대 3~4줄로 제한하며, 핵심 단어는 **오렌지 코랄(#FF6B3D)**로 강조합니다.
    *   *(예시: "사용자님의 이메일 주소 형식이 유효하지 않습니다.")*

### C. 해결 가이드 및 액션 버튼 (`Resolution & CTA`)
*   **섹션 제목:** `해결을 위한 조치 (Action Required)`를 명시합니다. H3 크기(18px).
*   **가이드 텍스트:** 오류의 원인에 대한 구체적인 해결 방법을 제시합니다. (예: "비밀번호는 영문, 숫자, 특수문자를 포함하여 최소 8자 이상이어야 합니다.")
    *   **강조 규칙:** 필수 수정 사항은 **굵게(Bold)** 처리하고, 설명 부분은 `(참고)`를 사용하여 가볍게 안내합니다.
*   **CTA 버튼 (`Retry/Back`):** 가장 중요한 액션입니다. 명확한 행동 유도 문구와 함께 배치하며, 배경색은 브랜드의 메인 강조색(`#3A4D72`, 딥 네이비)을 사용하고, 호버(Hover) 시 오렌지 코랄로 전환됩니다.

## 🧩 상태별 상세 스펙 (State-Specific Specs)

### 1. [Validation Error] - `HTTP 400`
*   **Title:** "입력 데이터 검증에 실패했습니다."
*   **Description:** 필수 필드가 누락되었거나 형식이 잘못되었습니다. 어떤 데이터를 수정해야 하는지 아래에서 확인하세요.
*   **Action Required:** (⚠️) **빨간색 테두리/배경 강조.** 오류가 발생한 특정 필드 옆에 작은 `❌` 아이콘과 함께 "유효하지 않은 입력" 레이블을 배치합니다. 사용자가 해당 필드를 클릭하면, 팝오버 형태로 구체적인 에러 메시지(예: "비밀번호는 최소 8자 이상입니다.")가 나타나야 합니다.
*   **CTA:** `수정 및 재검토` 버튼 (REVERT_TO_FORM).

### 2. [Precondition Failed] - `HTTP 412`
*   **Title:** "작업을 진행할 수 없습니다."
*   **Description:** 요청하신 작업을 수행하기 위한 전제 조건(예: 인증, 상태)이 충족되지 않았습니다. 현재 상황을 점검해 주세요.
*   **Action Required:** **상황에 따른 구체적 가이드 제시.** (예: "결제가 이미 완료된 계정으로 재신청할 수 없습니다. 관리자에게 문의해주세요.") 전제 조건이 무엇인지 명시하고, 이를 충족시키기 위한 절차를 안내합니다.
*   **CTA:** `상황 점검하기` 버튼 (REJECT_ACTION).

### 3. [Internal Server Error] - `HTTP 500`
*   **Title:** "시스템 내부 오류가 발생했습니다."
*   **Description:** 현재 저희 서버에서 요청을 처리하는 과정에 예상치 못한 문제가 발생했습니다. 죄송합니다. 잠시 후 다시 시도해 주시거나, 기술 지원팀에 문의해 주세요.
*   **Action Required:** **기술적 조치를 취할 수 없음을 안내.** 사용자에게 할 수 있는 유일한 것은 '재시도' 또는 '피드백 제공'임을 강조합니다. 오류 발생 시점의 스크린샷이나 로그를 캡처하여 피드백을 요청하는 필드를 포함합니다.
*   **CTA:** `나중에 다시 시도` 버튼 (WAIT_AND_RETRY)와 `문제 보고하기` 링크(Report Error).

## ✨ Figma 구현 가이드 요약
1.  모든 상태는 **Atomic Design 원칙**에 따라 컴포넌트화합니다.
2.  컬러 팔레트는 딥 네이비, 오렌지 코랄, 그리고 실패 시의 경고색(Red/Yellow)을 명확히 분리 사용합니다.
