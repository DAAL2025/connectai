# 🛠️ [Growth OS] 웹 개발 프로젝트 기술 부채 진단 체크리스트 (Top 20)
**목표:** 단순 기능 오류가 아닌, 비즈니스 성장 및 시스템 안정성을 저해하는 근본적 취약점을 식별한다.
**분류 기준:** 보안/인증(Security), 아키텍처/확장성(Architecture), 운영 흐름/효율성(Operation).

| # | 부채 항목 (Technical Debt) | 분류 | 상세 설명 및 위험도 | 잠재적 손실 비용 수치화 근거 |
| :---: | :--- | :--- | :--- | :--- |
| **I. 🛡️ 보안 및 신뢰성 취약점 (Security & Trust)** | | | | |
| 1 | **인증/인가 미흡 (Weak Auth/Auth)** | Security | 사용자 세션 관리, 비밀번호 해싱(Hashing), 역할별 접근 권한 분리 로직이 불완전함. (예: Admin 페이지 비공개) | 데이터 유출 시 법적 책임 및 고객 신뢰도 하락에 따른 **잠재 매출 손실액 ₩50M+** |
| 2 | **결제 웹훅(Webhook) 미검증 로직** | Security/Op. | PG사로부터의 결제 성공/실패 알림을 받았을 때, 실제 비즈니스 상태 변경 전에 재시도 및 검증 로직이 없음. (가장 흔한 운영 리스크) | 결제 누락 처리 실패 시 발생 가능한 **매출 미인식 손실액 (Transaction Loss)** |
| 3 | **XSS/CSRF 취약점** | Security | 사용자 입력값(댓글, 검색창 등)을 필터링하지 않아 악성 코드가 삽입되거나, 사용자가 원치 않는 요청에 속게 만듦. | 해킹 또는 데이터 조작으로 인한 시스템 마비 및 복구 비용 **₩10M+** |
| 4 | **API 키 하드코딩/노출** | Security | 민감한 API Key(OpenAI, Google Maps 등)를 프론트엔드 코드나 설정 파일에 평문으로 노출함. | 제3자에 의한 서비스 무단 사용 및 결제 시스템 오용 가능성 **₩5M+** |
| 5 | **비활성화된 계정 데이터 잔존** | Security/Arch. | 탈퇴한 사용자 계정의 개인 식별 정보(PII)가 안전하게 삭제되거나 익명화되지 않고 남아 있음. | GDPR 등 규제 준수 실패 시 발생하는 벌금 및 평판 손실 비용 |
| **II. 🏗️ 아키텍처 및 확장성 문제 (Architecture & Scalability)** | | | | |
| 6 | **모노리스 구조의 과부하** | Architecture | 모든 기능(CMS, 결제, API 게이트웨이 등)이 하나의 거대한 코드베이스에 묶여 있어, 특정 부분 수정 시 전체 시스템 위험도가 높음. | 작은 기능 업데이트에도 발생하는 개발 지연 시간 및 유지보수 비용 **증가율 (Cost Overrun)** |
| 7 | **데이터 스키마의 유연성 부족** | Architecture | 향후 추가될 서비스(예: 새로운 멤버십 등급, 상품군)를 수용하기 위해 데이터베이스 구조 자체의 변경이 필수적임. | 비즈니스 모델 변화에 대응하지 못해 시장 기회를 놓치는 **기회비용 (Opportunity Cost)** |
| 8 | **API 응답 시간 지연 (Latency)** | Architecture/Op. | 서버 간 통신이나 외부 API 호출(예: 배송지 검증) 시 적절한 캐싱 전략이 없어 사용자 대기 시간이 길어짐. | 페이지 로드 속도 저하에 따른 이탈률 증가 및 **전환율 하락 (CR Drop)** |
| 9 | **레거시 기술 스택 의존성** | Architecture | 최신 웹 표준(ES6+, React Hooks 등)이 아닌, 구형 라이브러리나 언어 버전에 종속되어 업데이트가 어려움. | 보안 패치 적용의 어려움과 신규 개발 인력 확보 비용 증가 **₩3M+** |
| 10 | **비동기 처리 로직 부재** | Architecture/Op. | 결제 완료, 뉴스레터 발송 등 시간이 걸리는 백그라운드 작업을 동기적으로 처리하여 사용자에게 시스템 지연을 체감하게 함. | 서비스 사용 만족도 저하로 인한 이탈률 증가 및 **VOC(Voice of Customer) 악화** |
| **III. 🚀 운영 흐름 및 경험 최적화 (Operation & Experience)** | | | | |
| 11 | **명확하지 않은 사용자 여정 (User Flow)** | Operation | '기술 부채 진단 신청'부터 '결제 완료'까지의 버튼 클릭이나 정보 입력 단계가 논리적으로 연결되지 않고 분산되어 있음. | 사용자가 핵심 목표에 도달하기 전 이탈하는 비율(Drop-off Rate) 증가 **% 지표** |
| 12 | **모바일 최적화 실패 (Responsiveness)** | Operation/Arch. | 데스크톱 환경에서는 완벽하지만, 모바일 기기 크기에 맞게 레이아웃이 깨지거나 조작이 어려움. | 전 세계 트래픽 중 모바일을 이용하는 비율을 고려한 **실질적 매출 손실액** |
| 13 | **에러 핸들링의 비전문성** | Operation/Security | API 호출 실패나 결제 오류 발생 시, "오류가 발생했습니다"와 같은 일반적인 메시지만 표시함. (사용자에게 혼란 유발) | 신뢰도 하락으로 인한 고객 문의 증가 및 **잠재 컨설팅 기회 상실** |
| 14 | **데이터 구조화 실패 (Taxonomy)** | Operation/Arch. | 수집된 리드 마그넷(Lead Magnet)이나 콘텐츠가 주제별, 난이도별로 체계적으로 분류되지 않고 혼합되어 있음. | 잠재 고객에게 필요한 정보에 도달하지 못하게 하여 **리드 육성 과정 실패** |
| 15 | **핵심 CTA의 가시성 부족 (Visual Hierarchy)** | Operation/UX | 페이지 전체에서 가장 중요한 행동 유도 버튼(CTA)이 배경색이나 배치상으로 눈에 잘 띄지 않음. | 방문자가 핵심 액션을 취하지 못하고 이탈하는 비율 증가 **% 지표** |
| **IV. 📈 성장 시스템 통합 부족 (Growth System Integration)** | | | | |
| 16 | **결제/CRM 연동의 불일치** | Operation/Arch. | 결제는 완료되었으나, 해당 고객 정보를 자동적으로 뉴스레터 목록이나 CRM(Customer Relationship Management) 시스템에 반영하지 못함. | 잠재적인 재판매 기회를 포착하지 못하고 사라지는 **LTV(Life Time Value) 손실** |
| 17 | **성과 측정 지표(KPI) 추적 미흡** | Operation/Arch. | 어떤 부분이 매출에 가장 크게 기여하는지 (예: 특정 페이지의 체류 시간, 버튼 클릭률 등)를 추적할 분석 코드가 누락되어 있음. | 문제점을 객관적으로 진단할 수 없어 **다음 마케팅 예산 집행 방향 오류** |
| 18 | **콘텐츠 업데이트 프로세스 부재** | Operation/Arch. | 콘텐츠(블로그, 사례 연구)를 발행해도 이를 체계적으로 분류하고 검색 엔진 최적화(SEO)하는 내부 운영 시스템이 없음. | 자연 유입 트래픽 확보 실패로 인한 장기적인 **유료 광고 의존성 증가** |
| 19 | **성과 기반 가격 책정 부재 (Pricing)** | Operation/UX | 서비스 가치를 '시간'이나 '노력'으로만 제시하고, 고객이 얻게 될 '비용 절감액'이나 '수익 증가분'을 수치화하지 않음. | 상품의 가치가 불분명하여 가격 협상에서 **불리한 위치**에 놓임 (가장 중요) |
| 20 | **사용자 피드백 루프 미구현** | Operation/Arch. | 웹사이트 내에서 사용자가 직접 문제점이나 개선 아이디어를 제안할 수 있는 공식적인 채널이 없음. | 고객과의 소통 부재로 인한 시장 변화에 대한 **민감도 저하 및 위험 예측 실패** |
