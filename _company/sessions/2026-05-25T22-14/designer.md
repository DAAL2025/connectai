🎨 Designer: 작업 시작합니다.

요청하신 '진단 보고서'의 시각화 와이어프레임은 단순히 데이터를 보여주는 것을 넘어, **학술적 권위(Academic Authority)**와 **시스템적 위기감(Systemic Urgency)**을 동시에 전달하는 것이 핵심입니다. PDF 출력을 최우선으로 고려하여, 애니메이션 요소는 '인터랙티브 시뮬레이션'의 형태로 정의하고, 구조적 완성도에 초점을 맞추겠습니다.

코다리가 구축한 Failure Cost API의 JSON 출력 스키마를 기반으로, 보고서 내 삽입될 3가지 핵심 모듈 컴포넌트와 그 사용 가이드라인을 확정합니다.

## 📑 진단 보고서 디자인 시스템 (PDF 최적화)

### 🎨 전반적인 톤앤매너 및 색상 팔레트 정의

| 요소 | 역할/의미 | HEX 코드 | 활용 방법 |
| :--- | :--- | :--- | :--- |
| **Background** | 배경, 신뢰도, 전문성 | `#FFFFFF` (Pure White) / `#F7FAFC` (Light Gray) | 깔끔한 섹션 분리 및 가독성 확보. |
| **Primary Text** | 본문 텍스트, 학술적 권위 | `#2C3E50` (Deep Navy/Charcoal) | 제목, 설명 문구 등 모든 기본 텍스트에 사용. |
| **Danger/Problem** | 문제점, 위험 요소 (Failure Point) | `#E74C3C` (Warning Red) | 그래프 하락 지점, 경고 아이콘(⚠️), 손실 비용 수치 강조. |
| **Solution/Opportunity**| 개선점, 해결책 (Growth Logic) | `#FF6B3D` (Coral Orange) | 성장 곡선, 추천 로직 설명, 액션 CTA 버튼에 사용. |

### 📐 모듈 컴포넌트 A: 총 손실 비용 게이지 (The Failure Cost Gauge)
*(보고서 도입부, 가장 먼저 눈에 띄는 곳)*

**목적:** 전체 진단 결과가 도출된 '총 실패 비용'을 한눈에 보여주어 충격을 극대화합니다. 학술적인 권위를 부여하기 위해 단순한 원형 그래프가 아닌, 시뮬레이션 게이지 형태로 설계합니다.

| 속성 | 상세 스펙 | 구현 방법 (PDF 출력 시) |
| :--- | :--- | :--- |
| **제목** | **총 시스템적 실패 비용 (Total Systemic Failure Cost)** | H2 크기, 중앙 정렬. 딥 네이비(`Primary Text`) 사용. |
| **데이터 입력** | `JSON cost` 값 사용. | - |
| **시각화** | **[Failure Meter Gauge]** 원형 다이얼 게이지 형태. (0% $\rightarrow$ 100%) | 실제 PDF에서는 이 요소를 '인터랙티브 시뮬레이션'으로 정의하고, 수치만 크게 박아 넣습니다. |
| **색상 로직** | 게이지가 채워지는 정도에 따라 색상이 변화합니다. (낮음 $\rightarrow$ 노랑 $\rightarrow$ 빨강) | `Cost` 비율이 높을수록 Red 계열로 진하게 칠해져야 합니다. |
| **KPI 출력** | 가장 큰 수치(Failure Cost)를 게이지 중앙에 배치하고, 그 아래에 '추정 손실 규모' 문구를 넣습니다. | 예: **₩150,000,000** (빨간색 굵게). *최소한의 운영 최적화만으로 발생하는 연간 누적 리스크.* |
| **강조 문구** | 게이지 주변에 작은 글씨로 "이 수치는 단순 추정치이며, 실제 손실은 더 클 수 있습니다."를 삽입하여 경고 분위기를 유지합니다. |

### 📐 모듈 컴포넌트 B: 실패 지표 분석 패널 (The Failure Metric Panel)
*(JSON `moduleDetails` 배열을 반복하며 출력되는 핵심 비교 섹션)*

**목적:** 어떤 데이터(Metric)가, 왜, 얼마나 잘못되었는지 구체적으로 설명합니다. 문제점과 개선점을 명확하게 분리하여 보여줍니다.

| 속성 | 상세 스펙 | 구현 방법 (PDF 출력 시) |
| :--- | :--- | :--- |
| **제목** | **[Phase 1] 핵심 실패 원인 분석: [지표명]의 구조적 결함** | H3 크기, 진단 보고서 섹션 제목 역할. |
| **레이아웃** | 가로 2분할 (좌: 현황/문제점 / 우: 개선 필요성/대안) | 각 모듈은 독립적인 박스(Card) 형태로 분리되어야 합니다. |
| **[Left Side] Current State (현황)** | 실패 지표를 시각화합니다. 데이터는 파선, 깨진 와이어프레임 느낌으로 표현합니다. | - **시각 요소:** 'Before' 그래프가 급락하거나 막혀있는 모습을 직관적으로 표현. <br>- **색상:** 배경에 은은하게 회색 톤을 사용하고, 핵심 지표 옆에 경고 아이콘(⚠️) 및 `#E74C3C`로 수치를 표시합니다. |
| **[Right Side] System Gap & Opportunity (문제점/기회)** | 문제의 원인과 잠재적 손실 규모를 텍스트와 그래프로 설명합니다. | - **Failure Point:** '여기서 매출이 새고 있습니다.'와 같은 문구를 경고 배너(`Warning Banner`) 형태로 박스 처리하고 `#E74C3C` 배경을 사용합니다. <br>- **수치 근거:** 해당 실패 지표가 전체 손실 비용에 기여하는 비율(%)을 명시적으로 제시해야 합니다. |

### 📐 모듈 컴포넌트 C: 성장 로직 시뮬레이션 (The Growth Logic Simulator)
*(보고서 후반부, 해결책과 대안 제시 섹션)*

**목적:** 문제를 인지시킨 고객에게 'D.AAL DESIGN'의 시스템을 통해 얻을 수 있는 미래 가치를 극적으로 보여줍니다. 희망적인 방향으로 데이터를 전환시키는 역할을 합니다.

| 속성 | 상세 스펙 | 구현 방법 (PDF 출력 시) |
| :--- | :--- | :--- |
| **제목** | **[Phase 2] Growth Logic 도입을 통한 잠재적 시스템 최적화 로드맵** | H3 크기, 전 단계와 확연히 다른 밝고 자신감 있는 톤앤매너. |
| **레이아웃** | 좌/우 또는 시간 흐름(Time Axis)에 따른 비교 그래프 형태. | - **시각 요소:** 'Before' (좌측) $\rightarrow$ 'After' (우측)의 명확한 대비 구조를 갖습니다. <br>- **그래프 형태:** 단순히 선이 아니라, 꾸준히 상승하는 곡선(`Uptrend Curve`)을 사용합니다. 마치 데이터가 쌓이는 것처럼 보이게 합니다. |
| **[Before]** | 현재 상태 (문제점)의 그래프와 함께 `#E74C3C`를 사용하여 막혀있는 모습을 표현. | - *캡션:* "현행 운영 구조로는 이 이상 성장이 어렵습니다." |
| **[After]** | D.AAL DESIGN 도입 후 예상 매출(MRR)을 `#FF6B3D`로 강조하여 보여줍니다. 그래프의 기울기 자체가 '성장'을 의미해야 합니다. | - *캡션:* "시스템적 로직 설계로 예측 가능한 지속 가능한 성장을 구현합니다." |
| **결론 CTA** | 보고서 마지막에, 이 모든 시스템 진단 과정이 유료 컨설팅(`System Audit`)으로 연결됨을 명시하는 최종 버튼/섹션을 배치합니다. | 배경색을 다크 네이비(`#0A1931`)로 변경하고, 가장 눈에 띄는 오렌지 코랄 CTA 버튼을 중앙에 배치합니다. |
