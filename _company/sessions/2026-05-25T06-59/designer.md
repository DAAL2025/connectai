# LAI 인터랙티브 시뮬레이터 디자인 사양서 (v2.0 - Error State 통합)

## 🎯 개요 및 목표 [Self-RAG 업데이트]
본 컴포넌트는 Loss Avoidance Index(LAI)를 실시간으로 계산하고 시각화하는 인터랙티브 대시보드입니다. 기존 V1에서는 'Happy Path'에만 초점을 맞추었으나, V2.0에서는 코다리가 정의한 **시스템 경계 조건 및 오류 상황**을 사용자 경험(UX)의 필수 요소로 통합하여, 시스템 신뢰성과 사용자의 이해도를 높이는 것을 목표로 합니다.

## 📐 컴포넌트 구조 (Component Structure)
### A. 메인 컨테이너 (Simulator Viewport)
*   **크기:** Desktop View 기준 1440px 폭 권장.
*   **배경:** 기본 배경색(#F7FAFC) 유지. 데이터 변화 시, 미묘한 'Data Flow' 애니메이션을 지속적으로 흐르게 하여 시스템의 역동성을 암시합니다.

### B. LAI 결과 표시 컴포넌트 (LAI Output Card) - [핵심]
*   **기본 상태:** "현재 예측된 Loss Avoidance Index: 78점" (오렌지 코랄 #FF6B3D로 강조).
*   **에러 상태 (Error State):**
    *   **조건:** `API Failure` 발생 시 (예: Rate Limit 초과, 데이터 불일치 등)
    *   **UI/UX:** LAI 수치가 사라지고, 중앙에 **경고 아이콘(⚠️)**이 크게 표시됩니다. 배경은 시스템 실패를 암시하는 미묘한 회색 톤(#EFEFF2)으로 전환됩니다.
    *   **메시지 컴포넌트 (Error Message Component):** 일반적인 에러 코드를 나열하지 않고, 사용자 친화적인 언어로 상황을 설명합니다. 예: "데이터 동기화에 실패했습니다. 원인: 데이터 불일치(412)." **→ 이 설명을 바탕으로 [Recovery Action] 안내.**
    *   **액션 버튼:** '재시도하기 (Retry)' 버튼이 활성화되며, 클릭 시 3초 카운트다운과 함께 재요청 로직을 수행함을 애니메이션으로 보여줍니다.

### C. 입력 데이터 제어 컴포넌트 (Input Controls) - [진행중]
*   **기본 상태:** 슬라이더/드롭다운 형태로 MRR, Churn Rate 등 변수를 조정합니다.
*   **유효성 검사 실패 상태 (Validation Failure State):**
    *   **조건:** 사용자가 입력 범위를 벗어나는 값을 넣었을 때 (`400 Bad Request` 예상)
    *   **UI/UX:** 해당 슬라이더나 입력 필드 아래에 **작은 빨간색 툴팁(Tooltip)**이 나타납니다. "⚠️ 값이 너무 높습니다. (최대치: 15% 이하로 설정해주세요.)" 와 같이 명확한 가이드라인을 제공합니다.

## 🔄 인터랙션 플로우 (Interaction Flow)
| 단계 | 발생 조건 | 사용자 경험 (UX) 변화 | 디자인 요소/애니메이션 | 근거 코드 |
| :--- | :--- | :--- | :--- | :--- |
| **1. 정상 데이터 흐름** | 입력 값 변경 $\rightarrow$ API 요청 성공 | LAI 점수 실시간 업데이트 및 그래프 부드럽게 애니메이션 변화 | 딥 네이비 배경 위에 오렌지 코랄 데이터 플로우 강조. | Happy Path (기존) |
| **2. 유효성 오류 발생** | 사용자 입력 값 범위 초과 | 즉시 피드백 제공, 수정 유도 | 입력 필드 하단 빨간색 경고 툴팁 및 포커스 변화. | `400 Bad Request` |
| **3. 시스템 데이터 불일치** | 백엔드에서 캐시/실시간 데이터 충돌 감지 | LAI 점수 표시 불가, 오류 메시지 활성화 | 전체 시뮬레이터 영역의 톤 다운 및 경고 컴포넌트 등장. | `412 Precondition Failed` |
| **4. 외부 서비스 중단** | 결제 API 등 의존성 실패 발생 | 명확한 상태 안내와 재시도 로직 안내 (시간 제한 표시) | '서비스 일시 중단' 문구와 함께, 재연결 시도 타이머(Timer)가 카운트 다운됨을 보여줌. | `503 Service Unavailable` |

## 📝 디자인 가이드라인 (Design Guidelines Update)
*   **에러 메시지 톤:** 기술적 용어 사용 금지. '시스템이 실패했다' 대신, '**사용자가 무엇을 해야 하는가**'에 초점을 맞춥니다. (예: "현재 데이터 동기화 문제로 정확한 예측이 어렵습니다. 잠시 후 재접속해 주세요.")
*   **색상 팔레트 추가:** 에러 상태용 **경고 색(Warning Color):** 🔴 `#FF4D4D` (활성 오류), **정보 색(Info Color):** 🔵 `#5B8CFF` (일반 안내).
