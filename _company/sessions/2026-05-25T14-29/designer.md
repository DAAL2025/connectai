# 📚 D.AAL DESIGN Master Component Library (v1.0)

## 🎯 목표: 학술적 권위와 정량화된 손실 비용 전달
**[근거: CEO 지시사항]**
모든 컴포넌트는 Navy Blue (`#0A1931`) 배경과 Coral Orange (`#FF6B3D`)의 대비를 활용하여, '진단(Diagnosis)'과 '해결책(Solution)'을 명확히 분리합니다. 폰트 계층 구조는 학술 논문 스타일을 따릅니다.

### I. 핵심 컴포넌트 (Core Components) 정의
이들은 모든 페이지에 재사용될 기본 빌딩 블록입니다.

1.  **[Component: 진단 메트릭 카드] Diagnostic Metric Card (DMC)**
    *   **용도:** 사용자의 현재 상태를 수치로 보여줄 때.
    *   **구조:** `(메트릭 이름) - [수치 값] / 100점` 형태로 표시됩니다. 수치가 낮을수록 위험도가 높음을 직관적으로 인지시킵니다.
    *   **UI/UX:** 카드 상단에 작은 **'위험도 지표 바(Risk Gauge)'**를 배치합니다. (예: 빨간색 → 노란색 → 초록색).
    *   **학술적 강조:** 메트릭 이름 아래에 `[진단 기준 출처: 시스템 운영 리스크 모델 v1.0]` 같은 작은 폰트를 넣어 신뢰도를 높입니다.

2.  **[Component: 비즈니스 플로우 다이어그램] Business Flow Diagram (BFD)**
    *   **용도:** 프로세스상의 병목 지점(Bottleneck)이나 데이터 누수 경로를 보여줄 때.
    *   **구조:** 노드(Node, 박스)와 방향성 화살표(Arrow)로 구성됩니다.
    *   **학술적 강조:** '문제 구간'에 해당하는 노드의 경계를 **미묘하게 깨진 파선(Glitch Effect)**으로 처리하고, 이 부분을 오렌지 코랄색(`FF6B3D`)의 점선으로 감싸서 시각적으로 불안정함을 표현합니다.
    *   **대비:** D.AAL DESIGN이 제안하는 개선 경로는 명확한 실선(Solid Line)과 딥 네이비를 사용해야 합니다.

3.  **[Component: 손실 비용 예측 모델] Failure Cost Simulation Widget (FCSW)**
    *   **용도:** 잠재적 매출 손실액을 시뮬레이션하고 정량화할 때. **(가장 중요한 컴포넌트)**
    *   **구조:** `(변수) $\times$ (빈도) \times$ (평균 손실률)` 공식을 간결하게 제시하는 미니 계산기 UI 형태입니다.
    *   **UI/UX:** 입력 필드에 값이 들어갈 때마다, 메인 결과 영역의 **'예상 연간 손실액(Predicted Annual Loss)'**이 오렌지 코랄색으로 실시간 업데이트되어야 합니다. 이 수치가 가장 크게 강조됩니다.

### II. '손실 비용 수치화'를 위한 3가지 핵심 레이아웃 (UI/UX)

#### 💡 Layout 1: [Mini Quiz 결과 페이지] - 진단 보고서 스타일
*   **목표:** 사용자에게 자신의 약점을 공포심과 호기심을 동시에 느끼게 하여, 컨설팅 요청을 유도.
*   **핵심 컴포넌트 사용:** DMC (진단 메트릭 카드) & FCSW (손실 비용 예측 모델).
*   **레이아웃 순서:**
    1.  **Diagnosis Summary (H2):** "당신의 비즈니스 시스템은 현재 [기술 부채]로 인해 예상치 못한 매출 손실을 겪고 있습니다."
    2.  **Top 3 Risk Report (DMC 그룹):** 상위 위험 요소 3개를 DMC 카드로 나열합니다. 각 카드 아래에 구체적인 `[근거: Researcher DB]`를 인용하여 전문성을 높입니다.
    3.  **Quantitative Loss View (FCSW 배치):** "만약 이 리스크가 개선되지 않는다면, 연간 최소 $[X]$원의 기회비용을 손실하고 계십니다." (수치 강조)
    4.  **CTA:** '전문 진단 보고서 요청 및 컨설팅 예약' 버튼에 **[Action: 시스템 감사]**라는 학술적 용어를 사용합니다.

#### 💡 Layout 2: [랜딩 페이지 - Pain Point 섹션] - 데이터 플로우 분석 스타일
*   **목표:** 일반 웹사이트의 한계를 '시스템 오류'로 규정하고, D.AAL DESIGN이 그 오류를 수정하는 전문가임을 각인시킵니다.
*   **핵심 컴포넌트 사용:** BFD (비즈니스 플로우 다이어그램) & DMC.
*   **레이아웃 순서:**
    1.  **Before State (문제점):** BFD를 사용하여 '일반적인 웹사이트'의 데이터 흐름을 그립니다. 결제 $\rightarrow$ 이메일 획득 $\rightarrow$ [단절] $\rightarrow$ 매출로 이어지지 않는 **누수 구간(Leakage)**을 오렌지 코랄색 파선과 경고 아이콘으로 강조합니다.
    2.  **After State (해결책):** BFD를 사용하여 'D.AAL ENGINE'의 데이터 흐름을 그립니다. 모든 과정에 데이터가 끊임없이 순환하며(Loop), 궁극적으로 MRR로 연결되는 명확한 실선 플로우입니다.
    3.  **Metric Comparison:** DMC를 활용하여 (Before State vs After State)의 핵심 지표(예: 전환율, 데이터 수집 깊이) 변화를 병렬 비교합니다.

#### 💡 Layout 3: [랜딩 페이지 - Growth Tier/결제 섹션] - 시뮬레이터 스타일
*   **목표:** 결제를 단순한 '비용'이 아닌, '미래 예측을 위한 투자(Investment)'로 인식시킵니다.
*   **핵심 컴포넌트 사용:** FCSW (손실 비용 예측 모델) & DMC.
*   **레이아웃 순서:**
    1.  **Intro:** "우리가 제공하는 것은 웹사이트가 아닌, **예측 가능한 성장 로직**입니다."
    2.  **Interactive Simulation (FCSW 중심):** 사용자가 'Growth Engine Retainer'의 월 금액을 입력하면, 시스템이 자동으로 해당 투자를 통해 얻게 될 `[최소 예측 매출 증가분]`을 계산하여 보여줍니다. 이 과정 자체가 **'투자 대비 효용성 시뮬레이터'** 역할을 합니다.
    3.  **Comparison:** DMC를 활용해 '단순 웹사이트 제작 비용 (X)'과 '시스템 구축 투자 (Y, 더 높음)'를 비교하되, Y가 제공하는 **미래 가치(Future Value)**에 오렌지 코랄색으로 높은 배율을 부여합니다.

### III. 디자인 시스템 가이드라인 업데이트 요약

| 요소 | 규칙/규정 | 세부 스펙 | 근거 |
| :--- | :--- | :--- | :--- |
| **메인 컬러** | Navy Blue (권위, 배경) | `#0A1931` | 학술적 권위를 위한 딥 네이비 유지. |
| **액션/강조 컬러** | Coral Orange (수익, 위험 경고) | `#FF6B3D` | '손실'과 '획득(Gain)'을 시각적으로 연결하는 핵심 색상. |
| **위험 표시 (Risk)** | Glitch Effect + 파선 | 오렌지 코랄색 점선 (`#FF6B3D`) | 시스템의 불안정성, 누수 지점 표현에 한정 사용. |
| **폰트 계층** | Serif 기반 학술적 폰트 | *Headline:* Playfair Display (Bold) / *Body:* Inter 또는 Noto Sans KR | 웹사이트 전체에서 통일된 전문성을 확보하기 위해 세리프/산세리프 혼합 구조 채택. |
| **데이터 시각화** | 그래프 및 다이어그램 | 모든 흐름은 **Directional Flow**를 따라야 하며, 수치는 반드시 `%` 또는 `$`와 함께 정량적으로 제시해야 합니다. | 시스템 컨설팅의 본질을 강조 (감성적 접근 금지). |
